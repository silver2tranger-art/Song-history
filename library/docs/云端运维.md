## URL 与静态网站

总首页对应 COS 根目录 `index.html`；分区为 `history/index.html`、`work/index.html`、`family/index.html`。宋史保留 `history/song/index.html` 及其相对图片路径。原仓库根目录 `index.html` 仍是宋史源码，构建时才映射到其旧线上路径。

CDN 必须使用已开启静态网站的 `cos-website` 源站；索引文档 `index.html`，错误文档 `404.html`。目录链接统一带尾部 `/`。普通对象源站的根目录可能返回 XML 或下载行为，不能替代静态网站源站。

全站采用真实静态目录，不把所有 404 重写到总首页。导入 SPA 优先采用 hash 路由；HTML5 history 路由需要针对该项目配置独立回退规则，不能使用全站 fallback 吞掉其他项目和撤回后的 404。

## 发布与缓存

工作流使用 GitHub Secrets `TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY`，密钥只通过环境变量传给官方 SDK，不写文件、不作为命令行参数、不打印完整 SDK 异常。

发布资源与内容后，更新门户；旧发布清单里有而新清单没有的对象被删除。首次迁移额外清理旧脚本误传的三份已知参考副本。不会枚举或清空整个桶，其他应用目录不会被同步删除。

`site-release.json` 只含公开的对象路径、项目 id、版本与 Git 提交号，用于重试及撤回。先写正在发布状态的对象并集，保证中断后下一次仍知道应清理哪些对象；最终成功后写完成状态。COS 多对象上传不是原子事务，更新期间可能短暂出现新旧混合；失败时先重跑当前 main 或正常 revert，不假称“全站瞬时切换”。

资源响应设置 `Cache-Control: no-cache, max-age=0, must-revalidate`。部署调用 `PurgePathCache` 强制刷新裸域名和 demo 的 HTTP、HTTPS 根目录，覆盖 HTML、资源和删除对象；轮询到 done，再验证线上页面实际含当前 Git 提交号。浏览器强制缓存规则可能覆盖源站头，应遵循源站。未加内容哈希，因此更新资产时特别依赖这些缓存策略。

## 最小权限

使用专门发布子账号，不使用主账号密钥。部署脚本只需要：

- `cos:GetObject`：读取 `site-release.json`；
- `cos:PutObject`：本系统根页面、`assets/library.css`、`assets/search.js`、各公开项目目录和 `site-release.json`；
- `cos:DeleteObject`：同范围内旧公开副本的撤回；
- `cdn:PurgePathCache`、`cdn:DescribePurgeTasks`：刷新目录和查询结果。腾讯云 CAM 将这两项定义为操作级权限，资源必须为 `*`，不能用域名资源 ARN 假装限制；脚本只提交 tztzxg.xyz 和 demo.tztzxg.xyz。

不需要删除桶、修改桶 ACL、管理用户/密钥、申请证书、修改 DNS 或 CDN 域名配置等权限。当前凭据的权限是否已收窄以实际 CAM 核查结果为准，文档不代表已经修改成功。新增私有桶不得交给此公开发布子账号。

## 域名和证书

裸域名、demo 的 CNAME 应指向各自在 CDN 控制台给出的值。不要把 CDN IP 固定为 A 记录，也不要把一个域名的 CDN CNAME 随意当另一个未接入域名的终点。

`www.tztzxg.xyz` 如以后启用：先接入独立 CDN 域名并部署覆盖 www 的证书，再配置 DNS，最后在支持的边缘重定向规则中将 www 301 到 `https://tztzxg.xyz`，保留 path 和 query。DNS 本身不产生 HTTP 跳转；HTTPS 连接发生在重定向之前，www 仍需要有效证书。

demo 当前作为兼容别名保留，旧 `/history/song/` 原样可用。新门户 canonical 指向裸域名。未来如改为 demo → 裸域名 301，必须保留完整 path/query，确认不存在 demo 专用应用后再实施。

正式切换后检查：裸域名首页、三个分区、宋史目录与 index.html、demo 旧路径、一个不存在的路径、Content-Type、HTTPS 证书、HTTP 跳转。浏览器持久保存的旧图片缓存或离线副本无法由 CDN 远程清除。
